# Threat Model Review — 2026-09-08 (Gate G0)

**Reviewed against:** [`docs/design/07_security_architecture_and_threat_model.md`](../../design/07_security_architecture_and_threat_model.md)
**Trigger:** Phase 0 gate review (`docs/design/07`'s stated cadence — "reviewed at each phase gate, and whenever a new trust boundary, external integration, or data class is introduced").
**Reviewer:** Founder / Head of Engineering (same sole reviewer named as policy owner across `docs/compliance/policies/`).

## What exists as of this review

An empty application: monorepo scaffolding, CI/CD gate set (lint, typecheck, test, secret scan, dependency scan + SBOM, SAST), a native `AuthProvider` (in-memory only, no persistence yet), and this policy/compliance documentation set. No database, no HTTP routes beyond the auth ones exercised by tests, no payment integration, no merchant or customer data of any kind.

## Trust boundaries assessed

Per `07`'s STRIDE model:

```
[Public internet] → [CDN/WAF] → [API] → [Database]
                                  ↓
                          [Stripe] [Identity provider] [Object storage]
```

- **Public internet ↔ API** — not yet a live boundary; no deployed endpoint exists outside test harnesses. No new finding.
- **Customer ↔ merchant data** — not yet applicable; no data model exists (`packages/db` starts D013, Phase 1).
- **Merchant ↔ merchant (tenant isolation)** — the critical boundary. Not yet testable because no repository layer exists yet; this is why Gate G1 (not G0) is where the generated cross-tenant test suite is the actual gate criterion. No premature claim of isolation is made here.
- **Application ↔ payment provider** — no integration exists (Stripe is Phase 5). Sub-processor status recorded as "not integrated" in `docs/compliance/subprocessors.md`.
- **Application ↔ object storage** — no integration exists (Phase 4).

**Conclusion: no new trust boundary has been introduced beyond what `07` already documents**, and none of the STRIDE table's threats are yet exercisable in a running system, because no running system with real data exists. This review's purpose at Gate G0 is to confirm the model is complete and current *before* any feature work begins — not to find findings in code that doesn't exist yet.

## What this review actually verified

- `07`'s STRIDE table (Spoofing/Tampering/Repudiation/Information Disclosure/Denial of Service/Elevation of Privilege) is internally consistent with what's now built: the authentication section correctly reflects ADR-002's native-`AuthProvider` decision (Argon2id, opaque sessions, mandatory MFA for `OWNER`/`ADMIN`) rather than the superseded managed-IdP assumption.
- The "Highest-priority controls" ranking (cross-tenant isolation → server-side pricing → webhook signatures → deposit capture bounds → condition-media integrity → hold-exhaustion limits) still matches the phase plan's build order in `docs/design/01`.
- No control in `07` depends on an assumption Phase 0's actual build has invalidated.

## Outcome

**No changes required to `docs/design/07`.** Filed as this cycle's dated review record per `07`'s stated cadence. Next scheduled review: Gate G1 (Phase 1 close), or sooner if a new trust boundary appears first.
