## Task

Mobile: Google and Apple sign-in buttons

## Deliverable

`expo-auth-session` (Google) and `expo-apple-authentication` (Apple, iOS only, per Apple's own platform restriction) wired into `SignInScreen.tsx`, calling D200's new endpoints. Apple's button is included alongside Google's per App Store Review Guideline 4.8 (any app offering third-party login must also offer Sign in with Apple).

## Acceptance criteria

Tapping either button completes a real OAuth round trip against a real Google/Apple account and lands signed-in on Home, on a real device or simulator/emulator — not just a mocked unit test. Acceptance criteria explicitly does not require this to be provable by an unattended headless session (real Google/Apple consent screens need an interactive browser); the log must say plainly what was and wasn't verified.

## Security check

Confirm the mobile client never handles or stores a raw Google/Apple client secret — only the public client ID and the provider's own SDK-issued identity token, verified server-side by D200.
