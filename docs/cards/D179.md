## Task

Break-glass grant workflow (backend)

## Deliverable

support_access_grants create/expire/revoke service; mandatory reason string with minimum length and no accepted placeholder value; fixed default expiry with a hard ceiling

## Acceptance criteria

A grant cannot be created without a validated reason; an expired grant is unusable even if not explicitly revoked; no renewal without a new reason

## Security check

Confirm every merchant-data call from apps/admin checks for an active, unexpired grant server-side, never trusting client state
