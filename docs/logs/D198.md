The tree-green check and the founder's resume note ("confirm PR #7's CI is green before trusting CI") surfaced two CI defects, both fixed in this run because every later card's gate depends on CI being trustworthy:

1. **`test (postgresql)` job — 76 of 101 db test files failed with `Failed to resolve entry for package "@smb-os/domain"`.** Root cause: the job ran `pnpm --filter @smb-os/db test`, which bypasses turbo and therefore skips `turbo.json`'s `test.dependsOn: ["^build"]` edge that builds `@smb-os/domain`'s `dist/` first. This job was added at D014 and, because the loop never pushed between D013 and the 2026-11-02 resume, had never actually executed on GitHub until PR #7 — a latent bug from day one, not a regression. Fix (`.github/workflows/ci.yml`): `pnpm turbo run test --filter=@smb-os/db`. Test-first: the existing D014 assertion in `packages/config/test/ci-workflow.test.ts` was flipped to require the turbo invocation and reject the bypass (it failed red against the old workflow, then green).
2. **`install, lint, typecheck, test` job — `packages/config` reported 70/70 tests passed but the run failed with `[vitest-worker]: Timeout calling "onTaskUpdate"`.** Root cause: `pre-push-hook.test.ts` (`execFileSync` of a real `pnpm audit` + whole-repo semgrep) and `sast.test.ts` (`spawnSync` of three ~20s semgrep scans) block the vitest worker's event loop for tens of seconds, so vitest's worker→main RPC times out and the file is marked errored despite passing. Fix: both now shell out with async `execFile` and `await`; same commands, same assertions, event loop stays responsive. Config suite: 70/70 green, no unhandled errors, pre-push test 9.4s, semgrep tests 3.9s/2.7s/7.5s.
