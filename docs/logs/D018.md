## Security check answer

**No password column on users — auth is delegated.** `users` (`packages/db/src/schema/{sqlite,pg}.ts`) has exactly `id`, `email`, `external_auth_id`, `status`, `created_at` — no `password` or `password_hash` column, matching `docs/design/03`'s explicit instruction and `07`'s note that credential verification is `AuthProvider`'s responsibility (`packages/domain/src/auth`, `apps/api/src/auth/NativeAuthProvider.ts`, D010), not this table's. `tenancy.test.ts`'s "has no password column on users" test asserts this against the real applied schema (`PRAGMA table_info` / `information_schema.columns`), not just a manual read of the migration file, so a future column addition here would fail the build rather than silently reintroducing password storage in the tenancy schema.
