## Acceptance criteria check

- **"PRAGMA values asserted by a startup test"** — met. `connection.test.ts` asserts `journal_mode` (`wal`), `foreign_keys` (`1`), and `busy_timeout` (`5000`) all read back correctly immediately after `createConnection` runs, plus a behavioral check that the FK pragma is actually enforced (not just reported), not only configured.

## Security check answer

**"foreign_keys ON — off by default in SQLite, a silent divergence from PG"** — addressed directly: `createConnection` sets `PRAGMA foreign_keys = ON` on every call, since the pragma is per-connection and resets to off each time a new connection opens (it does not persist in the database file). The test that matters most here isn't the pragma read-back — it's `connection.test.ts`'s fourth case, which creates a real parent/child table pair with a `REFERENCES` constraint and asserts that an insert violating it actually throws `FOREIGN KEY constraint failed`. A pragma that reads back `1` but isn't wired before any table access would still leave referential integrity silently unenforced; this proves enforcement, not just configuration.
