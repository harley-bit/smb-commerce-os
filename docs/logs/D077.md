## What happened

Built `packages/domain/src/payments/depositStateMachine.ts`, a pure domain state machine over `docs/design/03`'s `deposit_authorizations.state` enum: `AUTHORIZED | RELEASED | CAPTURED | PARTIALLY_CAPTURED | EXPIRED`. Same shape as D076's `damageClaimStateMachine.ts` — `applyDepositEvent` is the only path from one state to another, no exported setter, and every state but `AUTHORIZED` is terminal (single-capture enforcement per `docs/design/14`'s T3 risk). `CAPTURE` additionally carries an `amountMinor` and is checked against an injected `authorizedMinor` context: an amount that's non-positive or exceeds the authorized amount is rejected as an illegal transition (not a stored value) — this is `docs/design/07`'s "capture amount bounded by authorized amount" control made structural at the domain layer, and it also decides `CAPTURED` vs `PARTIALLY_CAPTURED` (full vs partial amount). Exported from `packages/domain`'s public `index.ts` alongside the other state machines. Wrote the failing test first (22 cases: each legal transition, capture-over-authorized rejected, zero/negative-amount capture rejected, every event rejected from every terminal state, the error's `fromState`/`event` fields, and the terminal-state set) — confirmed it failed on a missing module before implementing, then implemented until green. 100% statement/branch coverage (removed an unreachable `default` switch branch that TypeScript's exhaustiveness check makes redundant, since it was dragging branch coverage down without being reachable by any real input).

No repository/service/notification wiring in this card — the deliverable and acceptance criteria are domain-only ("Domain machine... Illegal transitions rejected"), same scope boundary D076's first session drew before being asked to close the repository/service gap in a second pass. ## Acceptance criteria check

- "Illegal transitions rejected" — **Met.** Every event from a terminal state (`RELEASED`/`CAPTURED`/`PARTIALLY_CAPTURED`/`EXPIRED`) throws `IllegalDepositTransitionError` (tested for all 4 states × 3 event types = 12 cases); a `CAPTURE` above the authorized amount, or with a zero/negative amount, throws the same error rather than transitioning (tested).
