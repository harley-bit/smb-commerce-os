## What happened

Scaffolded `apps/mobile` (`@smb-os/mobile`) as a real Expo/React Native workspace package (SDK 57, `expo-status-bar`, TypeScript strict), wired into the pnpm/turbo workspace with the same `lint`/`typecheck`/`test`/`test:isolation`/`build` script convention every other package follows. The app shell (`App.tsx`) imports `publicMerchantProfileSchema` directly from `@smb-os/contracts` — the same Zod schema `apps/web`'s storefront already validates the `GET /v1/m/{slug}` payload against — via a small `parseMerchantProfile` helper (`src/shell/parseMerchantProfile.ts`), test-first (`parseMerchantProfile.test.ts`, 2 cases: valid payload, schema-rejected payload). Wiring `@smb-os/contracts` into a real Metro bundle surfaced a genuine cross-platform gap: `@smb-os/contracts/variant.ts` imports `Money` from `@smb-os/domain`, whose barrel also exports `utils/uuid.ts`'s `generateUuidV7` (`node:crypto`'s `randomBytes`) — code the mobile shell never calls, but Metro has no dead-code elimination across a package boundary, so the whole graph must still resolve. Fixed with a `metro.config.js` resolver alias redirecting `node:crypto` to `src/shims/nodeCrypto.ts` (backed by `expo-crypto`'s synchronous `getRandomBytes`) — a resolution-only shim, documented as such, since `generateUuidV7` (ids are server-issued) is dead code on this client. `npx expo export --platform ios --platform android` then bundled cleanly for both platforms (Hermes bytecode, ~2.2MB each).
