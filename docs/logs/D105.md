## Security check answer

"Tenant-scoped query; no cross-merchant leakage" — this card added no new server-side query. `GET /listings` (`apps/api/src/routes/listings.ts`) already calls `ListingRepository.list`, which extends `TenantScopedRepository` and scopes every query to `ctx.merchantId` derived from the authenticated session plus the `X-Merchant-Id` header — the same mechanism the D021 cross-tenant isolation generator already exercises for every repository method, `ListingRepository.list` included, with zero gaps. This card's own contribution to the guarantee is on the client: `CatalogView` never accepts or derives a merchant id from anything other than its own `merchantId` prop (itself sourced only from the URL's `?merchantId=`, matching D104's precedent), and every fetch call sends that same id via `X-Merchant-Id` — there is no code path in this component that could address another merchant's listings.
