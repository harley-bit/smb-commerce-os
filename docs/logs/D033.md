## Security check answer

**Variant price is server-authoritative.** `VariantService.create`/`update` run every caller-supplied `priceMinor`/`currency` pair through `Money.of()` before it is persisted — `Money.of` throws on any non-integer minor-unit value (`packages/domain/src/utils/money.ts`), so a client cannot smuggle a float or otherwise malformed price into storage. `update()` re-validates using the *existing* row's currency when a patch doesn't supply one, so a partial price update can't silently combine an old currency with a new (unvalidated) amount. No method in this service accepts a pre-computed total or trusts a client-supplied value without running it through this check first — consistent with `CLAUDE.md`'s "prices and totals are always recomputed/validated server-side" rule. This card does not yet wire variant price into order-line computation (`D031`'s `computeLineTotal`/`assertLineTotal`) — that integration is future order-service work, flagged honestly rather than assumed done here.
