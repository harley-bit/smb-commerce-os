## What happened

Implemented the `AuthProvider` interface (`packages/domain/src/auth/AuthProvider.ts`, no I/O) and a `NativeAuthProvider` (`apps/api/src/auth/NativeAuthProvider.ts`) per ADR-002: Argon2id password hashing (`@node-rs/argon2`, prebuilt NAPI binary, no native build step), an opaque-token session model (server-side session store, httpOnly/Secure/`SameSite=Strict` cookie, real revocation), a hashed single-use 30-minute password-reset token, per-IP-and-per-account rate limiting on login and reset-request (`SlidingWindowRateLimiter`), progressive account lockout on repeated failed logins (`AccountBackoff`), and an Origin-header check on state-changing requests as the CSRF half ADR-002 allows in place of double-submit tokens. Persistence is in-memory (`apps/api/src/auth/repositories.ts`) behind `UserRepository`/`SessionRepository`/`ResetTokenRepository` interfaces — confirmed via design-doc research this run that real Drizzle/SQLite/Postgres wiring in `packages/db` is D013–D015 (Phase 1, after this card), so D010 cannot depend on it existing yet; the repository interfaces are the seam a later Drizzle-backed implementation swaps into without touching the provider or routes. All 33 new tests in `apps/api` and 3 new tests in `packages/domain` pass, including the full register → login → cookie → authenticated route → logout (revoked) → password-reset flow from the acceptance criteria, and a grep-based test proving no production module outside `NativeAuthProvider.ts` and the `app.ts` composition root references `NativeAuthProvider` by name. Full local gate (`pnpm lint && pnpm typecheck && pnpm test && pnpm test:isolation`, plus `pnpm build`, `pnpm audit --audit-level=high`, and `semgrep scan --config p/security-audit --error`) is green.

**What's explicitly not done:** TOTP-based MFA for `OWNER`/`ADMIN` roles, which ADR-002 lists as a hard requirement ("does not get to slip just because auth is native now"). This is a materially separate feature (secret provisioning/enrollment, QR/manual-entry flow, verification-code check gating login for those roles) that wasn't reachable in this run without cutting corners on the pieces above. Per the card's own guidance ("reasonable for this one to take more than a single run... say so honestly rather than cutting a corner"), this is carried rather than marked done.

## Acceptance criteria check

- Register, log in, receive a session cookie, access an authenticated route, log out (session revoked), request a password reset — all against `NativeAuthProvider`, with a passing test for each step: **Met.** (`apps/api/test/auth-flow.test.ts`)
- A test asserting no other module imports `NativeAuthProvider` directly (only the interface) passes: **Met.** (`apps/api/test/native-auth-provider-encapsulation.test.ts`)

Both literal acceptance criteria on the card pass. The card is still Carried because the security check below (which points to ADR-002's fuller requirement set) is not fully satisfied — MFA is missing.

## Security check answer

- Passwords are hashed with Argon2id, never bcrypt/SHA/plaintext: **Yes** — `@node-rs/argon2`, `Algorithm.Argon2id`, verified by a test asserting the stored hash matches `/^\$argon2id\$/` and never contains the raw password.
- Passwords never appear in logs, audit `before_json`/`after_json`, or error responses: **Yes for what exists today** — no audit log table exists yet (that's later Phase work), and a test asserts a failed-login error's message/stack never contains the attempted password. Fastify logging is disabled (`logger: false`) for this card; wiring real structured logging with password redaction is a follow-up when logging is actually added.
- Login and reset-request endpoints are rate-limited from this card: **Yes** — per-IP and per-account sliding-window limits on both endpoints, tested to actually return 429 past threshold.
- Session tokens are opaque and revocable server-side, not a long-lived unrevoked JWT: **Yes** — 32-byte random hex token, single-segment (not JWT-shaped), stored server-side with `revokedAt`; a test confirms `verifySession` returns `null` immediately after `revokeSession`.
- **Gap (why this card is Carried, not Done):** MFA (TOTP) for `OWNER`/`ADMIN` is required by ADR-002 and is not implemented. No corner was cut on the pieces that *are* built (Argon2id, real rate limiting, real revocable sessions) to force this card closed early.
