## What happened

Extended the `DepositHoldProvider` port (`packages/domain/src/payments/DepositHoldProvider.ts`) with `captureManualCaptureHold` and `releaseManualCaptureHold`, and added a new domain error `DepositHoldAlreadyResolvedError` (`packages/domain/src/payments/DepositHoldAlreadyResolvedError.ts`) — the provider-layer counterpart to `depositStateMachine.ts`'s `IllegalDepositTransitionError`. `SimulatedDepositHoldProvider` (`packages/db/src/payments/SimulatedDepositHoldProvider.ts`) now tracks each intent's own resolution (`AUTHORIZED | CAPTURED | RELEASED`) independent of `deposit_authorizations.state`: a capture or release on an intent it has already resolved throws `DepositHoldAlreadyResolvedError` before any state change, and a partial capture (amount below the held amount) computes and returns `releasedRemainderMinor` in the same call, mirroring real Stripe manual-capture semantics (capturing less than authorized auto-releases the remainder — there's no separate release step for it). Idempotency-key replay on capture returns the original result rather than re-resolving.

`DepositAuthorizationService` (`packages/db/src/services/DepositAuthorizationService.ts`) gained `captureHold` and `releaseHold`, wiring the provider calls to `DepositAuthorizationRepository.capture`/`release` (D078's domain-layer state machine, already built and already enforcing single-capture/bounds via `applyDepositEvent`). Both methods call the provider first, using `payment.providerRef` (the payment row created by D094's `placeHold`) as the `intentId`, then apply the resulting state to the deposit row — so a duplicate capture attempt is rejected by the provider before any domain-layer write is attempted a second time. `captureHold` also folds the capture into `payments.status` via D093's `applyProviderEvent` (`SUCCEEDED`). `DepositAuthorizationRepository.release` now returns the resulting `DepositState` (previously `void`) so callers can observe the terminal state, matching `capture`'s existing return shape.

## Acceptance criteria check

- "Partial capture releases remainder" — **Met.** `SimulatedDepositHoldProvider.test.ts` proves a $120/$200 partial capture returns `releasedRemainderMinor: 8000` in the same provider call (no separate release step). `DepositAuthorizationService.test.ts` proves the same end to end: capturing 12000 of a 20000 hold lands the deposit in `PARTIALLY_CAPTURED` with `capturedMinor: 12000` and the service result reports `releasedRemainderMinor: 8000`.
- "State correct" — **Met.** Full capture → `CAPTURED`; partial capture → `PARTIALLY_CAPTURED`; release → `RELEASED`, each verified against `DepositAuthorizationRepository.findById` after the service call, not just the returned value. A second capture attempt on an already-captured or already-released hold is rejected end to end and leaves the persisted row untouched.

## Security check answer

**"Single capture enforced at both domain and provider layers."** Domain layer: `DepositAuthorizationRepository.capture`/`release` (D078) route every transition through `applyDepositEvent`, which only accepts an event from `AUTHORIZED` — a second capture or a capture-after-release re-reads the current (already-terminal) state and throws `IllegalDepositTransitionError`, proven by pre-existing D078 tests and re-exercised here through the service. Provider layer (new this card): `SimulatedDepositHoldProvider` keeps its own per-intent resolution map, separate from anything the caller passes in, and throws `DepositHoldAlreadyResolvedError` on a second capture/release of the same `intentId` — proven by dedicated tests (`rejects a second capture attempt on an already-captured intent at the provider layer`, `rejects capturing an intent that was already released at the provider layer`, `rejects a second release attempt on an already-resolved intent`). Because `DepositAuthorizationService` calls the provider before the repository, a bug in either layer's enforcement alone cannot let a double capture reach persistence — proven end to end by `rejects a second capture attempt end to end — provider is never called twice and state stays put`.
