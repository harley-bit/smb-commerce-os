## What happened

Confirmed the tree was green (`pnpm lint/typecheck/test/test:isolation`, 10/10 tasks, all cached
or passing) before starting. Built the two pieces of this card that are actually implementable and
verifiable inside this repo without a GitHub remote: `.github/pull_request_template.md` with a
self-review checklist, and a Conventional Commits `commit-msg` hook (`.githooks/commit-msg`,
installed via the existing `prepare` → `git config core.hooksPath .githooks` wiring from D006).
Both were built test-first (`packages/config/test/pr-template.test.ts` greps the template for the
checklist/CC8/gate-step language; `packages/config/test/commit-message-format.test.ts` shells out
to the real hook script against valid and invalid commit messages, mirroring the D006/D007/D008
pattern of testing the real artifact, not a mock). The hook was also verified end-to-end for real:
this card's own commit ran through it live via the repo's already-active `core.hooksPath`, and it
accepted the conventional-format message.

The remaining piece — actual branch protection rejecting a direct push to `main` — was initially
carried (see below) because this repo had no GitHub remote and no `gh` access. **Resolved in a
later session, by explicit founder decision (outside CLAUDE.md's WHERE limits for the automated
loop, not this session acting unilaterally):** `gh` installed and authenticated, a real GitHub repo
created (`github.com/harley-bit/smb-commerce-os`, made public by founder choice — branch protection
on a private repo needs GitHub Pro), pushed, and branch protection applied to `main`.

**The first real push surfaced two genuine bugs, invisible in local-only testing:**

1. D008's SBOM test shells out to the real `syft` binary. `ci.yml` installed `syft` only in a later
   "Generate SBOM" step, after the `Test` step already ran — CI failed on the very first run, despite
   passing locally where `syft` was already on `PATH` via Homebrew. Fixed by moving the install next
   to the other tool installs (gitleaks), before dependency install/test.
2. gitleaks flagged D006's own deliberate test fixture (`AKIAABCDEFGHIJKLMNOP` in
   `packages/config/test/secret-scanning.test.ts`) as a real leak when scanning full history —
   correct behavior for real secrets, false positive for a known fake one. Fixed with
   `.gitleaks.toml`, an allowlist scoped to the exact literal string (not the file path, not a
   broader pattern), so a real secret anywhere — including that same file — is still caught.

Both fixes landed through a real PR (`#1`), which also caught a genuine **branch-protection design
flaw** before it could bite: `required_approving_review_count: 1` combined with `enforce_admins:
true` would have made this solo-maintainer repo unmergeable — GitHub never lets a PR author approve
their own PR, and `enforce_admins` removes the owner-override path. Corrected to
`required_approving_review_count: 0` (PR still required, direct push and force-push still rejected,
but a solo maintainer can merge). `required_status_checks` was also added afterward (`strict: true`,
naming the real CI job), so a PR genuinely cannot merge without CI passing and being current with
`main` — not just "a PR exists."

**Verified for real, not just configured:** a direct push to `main` was attempted from this repo and
rejected (`GH006: Protected branch update failed for refs/heads/main` — "Changes must be made
through a pull request"), then the test commit was undone locally (`git reset --soft`, never
pushed). PR #1 passed the required CI check and was merged solo, with no second reviewer, confirming
the corrected settings actually work for one maintainer.

The full process — branch → local gate → hooks → PR with self-review checklist → required CI →
solo merge → revert-only rollback — is now documented as policy, not just practice, in
`docs/design/17_change_management_policy.md`, with `docs/design/10`'s branching section corrected
to match and `docs/design/09`'s change-management control row pointing to it.

A fourth git hook, `.githooks/pre-push`, was added in the same pass: `pnpm audit --audit-level=high`
and semgrep SAST already existed in CI and in local fixture-driven tests (D007, D008), but nothing
stopped a vulnerable dependency or a flagged pattern from being *pushed* before this — now caught on
the developer's machine first, with CI as the backstop for a bypassed or missing hook. Test-first,
same pattern as the other hooks (`packages/config/test/pre-push-hook.test.ts`), including
PATH-manipulation tests for both "tool not installed" guard branches.

## Security check answer

"Self-review checklist is the CC8 change-management evidence" — answered by building
`.github/pull_request_template.md` so that the self-review checklist is the artifact a reviewer
(or the author, solo) checks off before merge, and stating explicitly in the template itself that
this checklist *is* the CC8 evidence, not a separate compliance document to keep in sync. Each item
maps to a concrete, checkable gate (lint/typecheck/test/isolation, dependency justification, no
secrets/card data, server-side price recomputation, Conventional Commits) rather than a vague
"reviewed it" checkbox. This was exercised for real on PR #1's own checklist, not just described.
