## What happened

Built `ProductSaleService` (`packages/db/src/services/ProductSaleService.ts`), the first caller of D040's `guardedDecrement` and D041's `transitionStatus` — closing the gap both those logs flagged. `sellProduct` gates on `inventory:manage` (D037 `assertCan`), looks up the variant by id (`VariantRepository`), rejects anything that isn't `mode: "PRODUCT"` (services/rentals sell through a different path), then computes `unitPriceMinor`/`currency` **exclusively** from that server-side variant row and `lineTotalMinor` as `unitPriceMinor * quantity`. `SellProductInput` has no price field at all, so a type-conforming caller cannot pass one; `guardedDecrement` records a `SALE` movement (reusing D040's negative-stock guard, so a sale can never take stock below zero), an optional `unitId` additionally routes through `InventoryUnitService.transitionStatus` to `SOLD` for serialized stock, and a hash-chained `audit_log` entry (`action: "inventory.sale"`) records the server-computed price. Test-first: `ProductSaleService.test.ts` (7 cases) was confirmed failing on `Cannot find module` before the file existed, then all 7 passed once implemented, including a case that hands the service a raw untyped payload carrying `priceMinor: 1`/`unitPriceMinor: 1` (`as never`, simulating a tampered HTTP body past the type system) and asserts the returned/audited price is still the variant's real 5000, not 1.

## Acceptance criteria check

- **Client-supplied price is ignored and the server value used** — Met. `"uses the server-side variant price and ignores a client-supplied price"` and `"audit-logs the sale with the server-computed price, not any client-supplied value"` both pass a payload with an injected `priceMinor`/`unitPriceMinor` of 1 and assert the returned `unitPriceMinor`/`lineTotalMinor` and the audit log's `afterJson` all reflect the variant's real server-side price (5000), never the injected value.

## Security check answer

**"THREAT: price tampering. Prices never accepted from the client."** Answered directly: `SellProductInput`'s type has no price field, so a conforming caller physically cannot supply one — and `sellProduct`'s implementation never reads any price-shaped key off `input` even if a raw/untyped payload carries one, only off `VariantRepository.findById`'s own row. Verified by a dedicated test that deliberately injects `priceMinor`/`unitPriceMinor` into the input (cast `as never` to bypass the type check, modeling a real HTTP body) and confirms both the returned result and the audit-log entry carry the server's price, not the injected one.
