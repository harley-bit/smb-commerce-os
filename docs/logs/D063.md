## What happened

`rate_period`/`deposit_minor` already existed on `listing_variants` from D022's original schema; this card's actual gap was `buffer_minutes` (`docs/design/05`'s rental turnaround gap — cleaning/inspection/charging, applied by expanding a reservation's effective interval at write time, per D064's future card). Added `bufferMinutes` (nullable `integer`) to `listing_variants` on both dialects, folded it into the existing `listing_variants_mode_fields_check` CHECK constraint alongside `rate_period`/`deposit_minor` (forbidden for `PRODUCT`/`SERVICE`, allowed for `RENTAL`), and threaded it through every layer that already mirrors that constraint: `VariantRepository`'s `Variant`/`CreateVariantInput`/`UpdateVariantInput` types, `VariantService`'s `FORBIDDEN_FIELDS_BY_MODE` map, and `packages/contracts`'s `FORBIDDEN_VARIANT_FIELDS_BY_MODE`/Zod schemas. `drizzle-kit generate` produced both migrations, but the SQLite one had a real bug: SQLite's table-recreate strategy for adding a column alongside a CHECK constraint generated an `INSERT ... SELECT buffer_minutes FROM listing_variants` that reads the new column name from the *old* table (which doesn't have it yet) — caught by the full `pnpm test` run (`no such column: "buffer_minutes"`), fixed by hand-editing the migration to select a literal `NULL` for that column instead of the column reference.

## Security check answer

Deposit amount is server-authoritative: `depositMinor` (pre-existing from D022/D033) is never accepted as a pre-computed total from any client-trusted path — `VariantService.create`/`update` run `assertValidPrice` (real `Money.of` from `@smb-os/domain`) on `priceMinor`/`currency` before persistence, and `depositMinor` itself is a plain server-stored integer column with no endpoint anywhere in this repo that reads it from an order/checkout payload — it is set once, by an `OWNER`/`ADMIN` catalog manager, through `VariantService`, the same authorization-gated path as every other variant field. No booking/checkout code (D050–D062) currently reads or recomputes `depositMinor` at all — that wiring (charging/holding the deposit at booking time) is future rental-lifecycle work, tracked, not assumed done here.
